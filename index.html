rubin-gpu-2pcf/Overview

GPU + AI for the Rubin era

A CuPy-accelerated engine for the angular two-point correlation w(theta), the clustering leg of a 3x2pt analysis. Bit-for-bit identical to CPU, cross-checked against TreeCorr, roughly 30 to 50 times faster on a Tesla T4, and run end to end on real Rubin DP1. Built to ride the data as it lands: DP2 this summer, DR1 next year.

Validated result

GPU ≡ CPU ≡ TreeCorr ≡ theory

The GPU result is bit-for-bit identical to CPU (0.00e+00), cross-checked against TreeCorr (2.7×10⁻⁴), and recovers the known analytic correlation to about 6 percent, run on real DP1 (~495k ECDFS objects via TAP).

Overview#

Rubin/LSST is the largest optical survey ever attempted: about 20 TB every night and roughly 20 billion galaxies mapped over a decade. The cosmology, dark energy, the nature of dark matter, and the galaxy to halo connection, lives in summary statistics computed across those catalogs. But the workhorse estimators are O(N²) CPU pair-counts, and they hit a wall exactly as the catalogs reach survey scale.

Pair counting is embarrassingly parallel, the textbook GPU win. This project puts that workload on the GPU with CuPy, starting from w(theta) and extending toward the AI / field-level inference the field is pivoting to.

Method#

The estimator is Landy and Szalay:

w(theta) = (DD - 2·DR + RR) / RR

where DD, DR, RR are normalized counts of data-data, data-random, and random-random pairs in bins of angular separation. The module provides two identical-algorithm backends behind a single xp handle, so the GPU result can be validated against the CPU one:

  • backend = cpu: NumPy, the bit-for-bit validation reference and speedup baseline (also runs in CI).
  • backend = gpu: CuPy, the deployment path (auto-selected when a device is present, for example S3DF A100/H100).

A separate, independent reference (TreeCorr, tree-based) provides the cross-check. Three independent implementations agreeing is the correctness gate.

Tracks#

  • DONEGPU 2-point clustering CuPy w(theta): GPU ≡ CPU ≡ TreeCorr ≡ theory, about 30 to 50x on a Tesla T4.
  • DONEReal DP1, end to end dp1.Object via TAP to w(theta) on ~495k ECDFS objects.
  • IN PROGRESSTomographic w(theta) Photo-z-binned clustering, the density leg of a tomographic 3x2pt, scaling to DP2.
  • IN PROGRESSAI / field-level inference (SBI) GPU forward-model to neural posterior, trained on 10⁴ to 10⁵ forward models. DP2-ready.
  • BUILTcuPhoton-style FITS ingestion kvikio + nvCOMP GPU decompression path, CPU-verified.
  • PLANNEDGNN / field-level on catalogs Graph-network inference on Rubin catalogs, the DR1 horizon.

Run#

GPU by default
The code auto-selects the GPU when one is present (for example KIPAC's S3DF A100/H100), which is the deployment path. The CPU path exists as the bit-for-bit validation reference, so it also runs on a laptop and in CI. Same code, one xp (CuPy or NumPy).
# + cupy-cuda12x on a GPU box
pip install -r requirements.txt

# measure + validate, then write a figure
python examples/run_demo.py

# CPU vs GPU speedup
python -m twopcf.bench

# AI / field-level: infer a parameter from clustering
python examples/run_sbi.py

# correctness gate
pytest -q

The compute

NSF + NVIDIA open AI for science; free GPU via NAIRR / DOE exascale.

Honest limits
The GPU w(theta) is validated and runs on real DP1. The AI/SBI track is an early scaffold (a ridge baseline today, with a neural-posterior estimator as the upgrade). Brute force is O(N²); the cell-list scales past it. A science-grade clustering measurement still needs the survey mask and star/galaxy separation.
